# Product screen map

551 literal JSX route records and 585 screen/composition files are indexed, not runtime accepted. Paths are relative to their routing scope, not automatically complete navigable URLs. Duplicate aliases, wildcard and inherited role guards remain in the inventory. Dynamic route generation is a discovery limit.

All route and screen items have dispositions in [routes](../../audit/routes.json) and [screens](../../audit/screens.json). Product-specific forms, approval flows, payroll, employee identity and permissions are documented only, not copied into the shared core. Superadmin and Flutter are separate implementation boundaries.

Five presentational candidates are provided in [patterns](../../packages/react/src/patterns.tsx). Dashboard metrics, approvals, uploads, conversations, rich text, calendars and Kanban compose shared primitives while retaining domain contracts in the host. A repeated HR pattern does not establish a Nvuto-wide policy.
